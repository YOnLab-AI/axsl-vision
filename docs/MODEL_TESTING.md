# 모델을 중심으로 시험하기

같은 모델에 여러 입력을 넣어 결과가 어떻게 달라지는지 확인하는 개발자용 흐름입니다. **모델 시험**에서 실행 ID를 먼저 고르고, 그 모델을 사용하는 기능과 자료 조건을 선택합니다. 여러 모델을 같은 입력에 실행하는 **모델 비교**도 계속 사용할 수 있습니다.

표시 버전은 **0.1**, 이 흐름을 추가한 내부 버전은 **code21**입니다. 이전 공개 APK **0.1/code20**의 시험 결과와 구분합니다. 새 빌드·기기 시험의 결과는 [버전별 검증 기록](VALIDATION.md)에서 확인하세요.

이 업데이트의 배포 구분자는 태그 `v0.1-build21`, APK `AXSL-Vision-0.1-build21.apk`입니다. 이전 `v0.1` APK와 고정 자산 pack을 덮어쓰지 않습니다. 실제 게시된 파일과 체크섬은 [Releases](https://github.com/YOnLab-AI/axsl-vision/releases)에서 확인합니다.

## 시작 순서

1. 홈에서 **모델 시험** 진입 버튼을 엽니다.
2. **시험할 모델**에서 표시명과 실행 ID를 확인합니다. 동일 가중치를 여러 기능이 공유할 수 있으므로, 이름만으로 다른 모델이라고 세지 않습니다.
3. **시험 기능**에서 선택한 ID를 지원하는 기능을 고릅니다. 관계없는 기능은 이 목록에 표시하지 않습니다.
4. 현재 구성의 안내를 읽고 **조건별 6개** 또는 **전체 목록**에서 자료를 선택합니다. **자료 선택 · 내 파일**로 개인 입력도 사용할 수 있습니다.
5. **이 자료로 시험**을 누릅니다. 실제 기능 controller에서 선택한 모델·입력으로 실행하고 결과·실패 상태를 확인합니다. 실행 중에는 해당 화면의 중지·닫기를 사용합니다.
6. 돌아와 자료만 바꾸어 다시 시험합니다. **이 모델의 시험 기록**에서 같은 실행 ID의 여러 입력 결과를 확인합니다.

시험할 모델은 자료의 KO/GO 구분으로 자동 교체하지 않습니다. 예를 들어 Vosk 한국어를 고른 뒤 글로벌 음성을 선택해도 영어 Vosk로 바꾸지 않습니다. 다른 언어 자료에 대한 실행은 언어 조건 차이 시험이며, 해당 모델이 그 언어를 지원한다는 뜻은 아닙니다. 입력 형식·기기·모델 조건을 만족하지 않으면 오류 상태나 안내를 확인하고 기록합니다.

모델별 기록과 공유는 같은 실행 ID로 범위를 제한합니다. 새 이미지·소리 보고서는 실제 실행한 각 모델 ID에 연결됩니다. 모델 ID가 없던 과거 저장 보고서를 임의로 특정 모델에 연결하지 않으며, 그런 보고서는 홈의 전체 **리포트 → 저장된 리포트**에서 확인할 수 있습니다.

## 화면 안내의 공통 형식

| 표시 | 확인할 내용 |
|---|---|
| 시험 기능 | 어떤 작업인지와 목적 |
| 시험 모델·엔진 | 실제 표시명, 안정적인 실행 ID, 선택 구성의 설명 |
| 실행 방식 | 실제 runtime과 학습 모델·복합 파이프라인·코드 엔진 구분 |
| 입력 조건 | 해당 기능이 받는 자료와 바꾸어 볼 조건 |
| 결과 해석 | 출력이 뜻하는 범위와 이 입력으로 평가할 수 없는 항목 |

**기본 선택**은 최초 실행에 사용하는 기본값입니다. 해당 기기에서 더 빠르거나 더 정확하다고 검증한 순위가 아닙니다. 상세 가중치·전후처리·출처는 [모델 카탈로그](MODEL_CATALOG.md)를 확인하세요.

Android Media는 재생 엔진이고 ZXing·OpenCV QR은 코드 해독 엔진입니다. 이런 실행 ID가 목록에 포함된다고 해서 모두 독립적인 신경망이나 학습 가중치가 있는 모델은 아닙니다.

## 다양한 자료 고르기

필터는 현재 선택 모델을 바꾸지 않고 자료 목록만 바꿉니다.

| 선택 | 동작 |
|---|---|
| 전체 자료 | 해당 기능이 지원하는 모든 자료 그룹 |
| 한국 자료(KO) / 글로벌 자료(GO) | 선택한 그룹과 공통 SHARED 자료 |
| 공통 자료 | SHARED 자료만 |
| 모든 입력 / 사진·영상·음성 | 선택 기능이 지원하는 입력 형식으로 제한 |
| 모든 조건 / 쉬움·보통·어려움·대조군·난도 미표기 | 데모에 기록된 난도로 제한 |
| 조건별 6개 | 난도·그룹·입력 형식·조건 태그의 차이를 우선하여 최대 6개 선택 |
| 전체 목록 | 처음 최대 12개를 표시하고 **자료 더 보기**로 12개씩 늘림 |

자료가 적으면 표시 개수도 줄어듭니다. 조건별 선택은 기록된 메타데이터의 차이를 늘리는 방식이며 무작위 표본, 성능 예측, 균형 잡힌 평가 데이터셋을 뜻하지 않습니다. 빈 목록에서는 필터를 바꾸거나 내 파일을 선택하세요.

각 카드에서 자료 ID·형식·그룹·난도·조건과 참조값 상태를 확인할 수 있습니다.

- **검증됨:** 카탈로그에 해당 입력과 연결된 검증 참조값이 있습니다. 그 사실만으로 모든 기능의 정확도를 계산할 수 있는 것은 아닙니다.
- **미검증 참고값:** 읽거나 비교할 참고 내용이며 정답으로 확정하지 않습니다.
- **정답 없음:** 실제 출력을 관측하고 실패·차이를 기록합니다. 분류 점수나 객체 수를 정확도로 바꾸지 않습니다.

자료를 열 때 `DemoStore`가 encoded 파일의 크기와 SHA-256을 확인합니다. 난도·흐림·가림 등의 태그는 입력 조건이며 모델 인식 성공률이 아닙니다. KO/GO는 자료·언어 구분이며 사람의 국적을 뜻하지 않습니다.

## 시험 설계 예

다음은 실행 방법의 예이며 이 문서에서 완료한 성능 시험 결과가 아닙니다. 제공되는 조건의 수는 선택 기능과 필터에 따라 달라집니다.

| 시험할 ID 예 | 바꾸어 볼 입력 | 기록할 관측 |
|---|---|---|
| `mobilenet-v4-fp32` | 다른 장면, 흐림·밝기·구도 차이 | Top1·Top5 후보와 점수, 입력별 처리 시간 |
| `efficientdet-lite0` | 대상 크기·가림·장면 복잡도 | 상자·분류·개수, 놓친 대상이나 잘못 찾은 대상의 관측 |
| `paddle-ocr-v6-ko` | 문자 크기·회전·흐림 | OCR 원문, 검증 정답이 있는 경우의 지원 지표 |
| `zxing-qr` | 코드 크기·회전·가림 또는 코드가 없는 대조군 | 해독 여부·코드 형식·원문 일치 여부 |
| `vosk-ko-small-0.22` | 발화 길이·속도·잡음·언어 차이 | 인식 원문·실행 상태, 정답이 검증된 경우 CER |
| `yamnet-classifier` | 생활 소리 종류·음량·다른 소리의 혼합 | 구간별 후보·점수, 어떤 소리가 혼동되는지 |

처음에는 모델 하나와 작은 자료 집합으로 실행 경로를 확인하고, 자료 조건을 하나씩 넓히세요. 모델을 바꾼 비교에서는 같은 입력 hash인지 먼저 확인합니다. YAMNet과 PANNs처럼 분류 체계가 다른 모델의 점수, 검색 모델의 서로 다른 특징 공간 점수를 같은 확률로 비교하지 않습니다.

## 모델 구성 시험과 전체 기능의 차이

모델 하나의 실행을 확인하는 것과 기능 전체를 수락하는 것은 다릅니다.

| 기능 | 구분할 범위 |
|---|---|
| 얼굴 비교 | 단일 사진의 모델 시험은 얼굴 검출·특징 추출입니다. 두 얼굴 선택과 코사인 유사도 대조는 전용 얼굴 비교 화면에서 실행합니다. |
| 사람 흐름·방문자 집계 | 모델 시험의 기본 자료 목록은 기능이 지원하는 영상 형식을 따릅니다. 별도 사진 모델 비교는 검출·특징 관측이며 기준선 통과·방문 세션·체류 시간 집계가 아닙니다. |
| 드라이버 관측 | 사진은 한 시점의 눈·입·고개 관측입니다. 깜박임·눈 감음 지속 시간은 영상·실시간 경로에서 시험합니다. |
| 운동 자세 코치 | 사진의 관절 각도·좌우 상태를 관측합니다. 반복 횟수·운동 효과·건강 상태의 평가가 아닙니다. |
| 안내판 | 사진·영상 재생과 전체 화면·전환 동작을 시험합니다. 선택적 관객 분석은 별도의 관측 구성입니다. |

기능별 입력과 전체 처리 흐름은 [FEATURES](FEATURES.md), 시간 상태와 controller의 연결은 [ARCHITECTURE](ARCHITECTURE.md)를 확인하세요.

## 같은 모델의 기록 읽기

**이 모델의 시험 기록**은 같은 실행 ID의 기록으로 범위를 좁힙니다. 다른 기능이 같은 ID를 사용한 기록도 포함할 수 있으므로 기능명과 입력 hash를 함께 읽습니다. 이 화면의 HTML·CSV 공유에도 같은 모델 범위를 적용합니다. 완료·오류와 저장된 보고서를 구분하며, 저장하지 않은 실행에 보고서 파일이 있다고 가정하지 않습니다.

다음 항목을 함께 남기면 다른 입력의 차이를 설명하기 쉽습니다.

- 앱 버전·내부 빌드 번호·APK SHA, 선택 실행 ID와 실제 모델/파이프라인 식별자.
- 자료 ID와 encoded 입력 SHA, 그룹·형식·난도·조건·참조값 상태.
- 실행 완료·오류·중지 상태와 출력 관측.
- 모델 준비·추론·전체 처리 시간 및 해당 시간의 측정 범위.
- 기기 모델/API와 CPU 요청 설정. SDK 내부 scheduling은 SDK가 관리하므로 CPU 요청값만으로 실제 가속기를 확정하지 않습니다.

정지 이미지의 기록 시간은 source decode를 제외한 모델 구성·전처리·추론·후처리 범위일 수 있습니다. 음성의 `PREDECODED_SAME_PCM_ENGINE` 시간은 이미 준비된 동일 PCM의 engine 실행이며 입력 준비/decode 시간과 구분합니다. **encoded 파일 SHA와 PCM SHA도 서로 다른 식별자**입니다. 다른 시간 범위의 숫자를 직접 순위로 만들거나 한 번의 값을 반복 benchmark·FPS로 바꾸지 않습니다.

## 개발자가 확인할 연결

| 구현 | 책임 |

| [OneTestSamples](../vision/src/main/java/com/yonlab/vision/OneTestSamples.java) | 자료 메타데이터 필터와 다양성 선택 |
| [OneModelTestPolicy](../vision/src/main/java/com/yonlab/vision/OneModelTestPolicy.java) | 입력을 바꿀 때 모델·선택 집합을 유지하는 정책 |
| [OneGuidance](../vision/src/main/java/com/yonlab/vision/OneGuidance.java) | 현재 기능·모델 안내의 공통 표시 |
| [OneLaunch](../vision/src/main/java/com/yonlab/vision/OneLaunch.java) | `openTest`에서 ID와 `keep_model` 맥락을 실제 controller로 전달 |
| [OneReportsActivity](../vision/src/main/java/com/yonlab/vision/OneReportsActivity.java) | `model_id` intent를 받아 같은 ID의 기록·공유 범위 구성 |

앱에 포함되는 [model-guide.json](../vision/src/main/assets/one/model-guide.json)은 [model-catalog.json](model-catalog.json)의 ID·이름·실행 종류·runtime·지원 기능에서 생성합니다. 과거 validation 결과나 성능 순위를 앱 안내에 복사하지 않습니다. 문서의 runtime 정보를 바꾼 경우 다음 명령으로 동기화하고 확인합니다.

```sh
python tools/sync_model_guide.py
python tools/sync_model_guide.py --check
python -m unittest discover -s tools/tests -v
```

새 모델이나 입력을 추가할 때는 [자료 이용 조건](DATA_AND_LICENSES.md), [재현 빌드](BUILD_AND_REPRODUCE.md), [검증 범위](VALIDATION.md)를 함께 갱신합니다. 개인 사진·얼굴 특징·음성 원문·장치 식별 정보는 공개 시험 자료로 자동 포함하지 않습니다.
